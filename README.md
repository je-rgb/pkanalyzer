# PK Analyzer

**Python 기반 MPEG-2 Transport Stream(TS) 분석 도구**

PK Analyzer는 MPEG-2 Transport Stream(TS) 파일의 패킷 구조와 스트림 정보를 분석하고, 패킷 오류 및 PID별 통계를 GUI 환경에서 확인할 수 있도록 개발한 프로젝트입니다.

TS 파일을 직접 파싱하여 패킷 헤더, PID, PAT/PMT, 미디어 스트림 정보 등을 확인하고, Sync Loss와 Continuity Counter(CC) 오류를 검사합니다. 분석 결과는 PySide6 기반 GUI의 탭별 화면으로 제공하여 스트림의 구성과 이상 여부를 직관적으로 파악할 수 있도록 설계했습니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | PK Analyzer |
| 프로젝트 유형 | MPEG-2 TS 파일 분석 도구 |
| 개발 언어 | Python |
| GUI 프레임워크 | PySide6 |
| 주요 기술 | 바이너리 파일 처리, 비트 연산, TS 패킷 파싱, 데이터 검증 |
| 분석 대상 | MPEG-2 Transport Stream (`.ts`) |
| 개발 환경 | WSL Ubuntu, Visual Studio Code |

### 개발 목적

MPEG-2 TS 파일은 방송 및 영상 전송에 사용되는 데이터 형식으로, 다수의 패킷이 하나의 스트림을 구성합니다.

TS 파일을 분석하려면 패킷 헤더에서 PID와 제어 정보를 추출하고, 프로그램 정보 테이블을 해석하여 영상·음성 스트림의 구성을 파악해야 합니다. 또한 Sync Byte와 Continuity Counter를 검사하여 패킷 구조의 이상이나 데이터 연속성 문제를 확인할 수 있어야 합니다.

본 프로젝트는 이러한 분석 과정을 Python으로 구현하고, 결과를 GUI로 시각화하여 사용자가 TS 파일의 구조와 주요 오류 정보를 쉽게 확인할 수 있도록 하는 것을 목표로 합니다.

## 2. 주요 기능

### 2.1. TS Packet 분석

MPEG-2 TS 파일을 188바이트 단위로 읽고 각 패킷의 헤더 정보를 추출합니다.

- **Sync Byte 검증:** 패킷 시작 바이트가 `0x47`인지 확인
- **PID 추출:** 패킷이 전달하는 프로그램 및 스트림 데이터의 식별자 추출
- **PUSI 분석:** Payload Unit Start Indicator 확인
- **AFC 분석:** Adaptation Field Control 값 확인
- **CC 추출:** Continuity Counter 값 확인
- **헤더 정보 확인:** TEI, 우선순위, Scrambling Control 등 주요 필드 분석

분석한 패킷 정보는 GUI의 패킷 목록에서 확인할 수 있습니다.

### 2.2. PID 분석 및 통계

PID(Packet Identifier)는 TS 패킷이 어떤 종류의 데이터 스트림에 속하는지 구분하는 데 사용됩니다.

본 프로젝트는 패킷을 분석하면서 PID별 패킷 수를 집계하고, 프로그램 정보와 대조하여 스트림 구성을 확인합니다.

- PID별 패킷 개수 집계
- PID별 패킷 비율 계산
- PAT/PMT에 등록된 PID 정보 활용
- PMT에 정의되지 않은 PID 식별 및 집계

PID 통계를 통해 TS 파일에서 어떤 PID가 사용되는지, 각 PID가 전체 패킷에서 어느 정도의 비중을 차지하는지 파악할 수 있습니다.

### 2.3. PAT/PMT 분석

PAT(Program Association Table)과 PMT(Program Map Table)는 TS 파일에 포함된 프로그램과 미디어 스트림의 구성을 파악하는 데 사용되는 주요 테이블입니다.

**PAT 분석**
- 프로그램 번호 확인
- 프로그램별 PMT PID 추출
- Network PID 정보 확인

**PMT 분석**
- PCR PID 확인
- Elementary Stream의 PID 추출
- Stream Type을 기반으로 미디어 종류 및 코덱 정보 식별
- ISO 639 언어 디스크립터를 통한 언어 정보 추출

이를 통해 TS 파일에 포함된 프로그램과 영상·음성 스트림 간의 관계를 확인할 수 있습니다.

### 2.4. 미디어 스트림 정보 분석

PMT의 Stream Type 정보를 바탕으로 지원하는 주요 미디어 유형을 식별합니다.

| Stream Type | 식별 정보 |
|---|---|
| `0x02` | MPEG-2 Video |
| `0x1B` | H.264 Video |
| `0x24` | H.265 Video |
| `0x0F` | AAC Audio |
| `0x11` | LATM AAC Audio |
| `0x03` | MPEG Audio |
| `0x04` | MPEG-2 Audio |
| `0x81` | AC-3 Audio |
| `0x06` | Private / Subtitle / Teletext 관련 스트림 |

분석 결과는 PID, 프로그램 번호, 코덱, 미디어 유형, 언어 정보로 정리하여 GUI에서 확인할 수 있습니다.

※ 위 정보는 Stream Type을 기반으로 한 식별 결과이며, 실제 미디어 데이터의 디코딩이나 재생을 수행하는 기능은 아닙니다.

### 2.5. 패킷 유효성 및 오류 검사

TS 파일을 분석하면서 패킷의 동기화 상태와 연속성 정보를 검사합니다.

**Sync Loss 검사**
- 패킷 시작 위치에서 Sync Byte 확인
- 예상한 Sync Byte와 다른 값이 발견되면 오류 기록
- 다음 유효한 패킷 위치를 탐색하여 재동기화 시도
- Sync Loss 발생 위치와 건너뛴 바이트 정보 기록

**Continuity Counter 검사**
- PID별 이전 CC 값과 현재 CC 값 비교
- Payload가 포함된 패킷의 CC 증가 규칙 검사
- 예상 값과 실제 값이 다른 경우 오류로 집계

**기타 검사**
- PMT에 정의되지 않은 PID 집계
- 불완전한 마지막 패킷 감지
- 파일 접근 및 파싱 과정에서 발생하는 오류 처리

이러한 검사를 통해 TS 파일의 구조적 이상과 패킷 연속성 문제를 확인할 수 있습니다.

> CC 오류는 연속성 검사 규칙에 따른 이상을 의미합니다. 모든 CC 오류가 실제 패킷 손실을 확정하는 것은 아니며, 스트림의 특성과 불연속성 정보 등을 함께 고려해야 합니다.

## 3. GUI 구성

PySide6를 사용하여 TS 파일 선택부터 분석 결과 확인까지 하나의 GUI에서 수행할 수 있도록 구현했습니다.

| 화면 | 주요 내용 |
|---|---|
| 패킷 목록 | 패킷 번호, PID, PUSI, AFC, CC 등 패킷별 정보 |
| PID 통계 | PID별 패킷 수 및 비율 |
| 미디어 스트림 정보 | 프로그램, PID, 코덱, 미디어 유형, 언어 |
| Sync Loss | 동기화 오류 발생 정보 |
| Unknown PID | PMT에 정의되지 않은 PID 목록 및 집계 |
| 분석 요약 | 전체 패킷 수와 주요 분석·오류 정보 |

### 사용 흐름

1. GUI에서 분석할 TS 파일을 선택합니다.
2. 분석기가 파일을 순차적으로 읽어 패킷 헤더를 파싱합니다.
3. PID 통계와 PAT/PMT 기반 스트림 정보를 수집합니다.
4. Sync Loss와 CC 오류를 검사합니다.
5. 분석 결과를 각 탭에 나누어 표시합니다.

패킷 상세 목록은 화면에 표시할 데이터를 제한하여 구성했으며, 전체 파일 분석 결과와 GUI 표시용 패킷 목록은 구분됩니다.

## 4. 기술적 구현

### 바이너리 파일 처리

TS 파일을 텍스트가 아닌 바이너리 모드(`rb`)로 읽고, 고정 길이 패킷 단위로 데이터를 처리합니다.

### 비트 연산을 활용한 헤더 파싱

TS 헤더에 포함된 비트 필드를 마스킹과 시프트 연산으로 추출합니다.

예를 들어, PID는 헤더의 두 번째 바이트 하위 5비트와 세 번째 바이트를 결합하여 계산합니다.

```python
pid = ((packet[1] & 0x1F) << 8) | packet[2]
```

이를 통해 바이너리 데이터에서 필요한 필드를 직접 추출하고, 프로토콜의 데이터 구조를 코드로 구현했습니다.

### PID 기반 스트림 매핑

PAT에서 프로그램별 PMT PID를 확인하고, PMT에서 각 Elementary Stream의 PID와 Stream Type을 추출합니다.

추출한 정보를 PID별 통계 및 미디어 스트림 정보와 연결하여 TS 파일의 구성을 파악할 수 있도록 했습니다.

### 분석 로직과 GUI 분리

- `analyzer.py`: TS 파일을 읽고 패킷·PID·프로그램·미디어 스트림 정보를 분석
- `gui.py`: 분석 결과를 탭과 테이블 형태로 표시
- `main.py`: QApplication을 초기화하고 GUI 실행

분석 로직과 화면 표시 로직을 별도 파일로 분리하여 기능별로 코드를 관리할 수 있도록 구성했습니다.

## 6. 실행 방법

### 6.1. 저장소 복제

```bash
git clone https://github.com/je-rgb/pkanalyzer.git
cd pkanalyzer
```

### 6.2. 가상환경 생성 및 활성화

Python이 설치된 환경에서 다음 명령어를 실행합니다.

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows 환경에서는 다음 명령어로 가상환경을 활성화할 수 있습니다.

```powershell
.venv\Scripts\Activate.ps1
```

### 6.3. 의존성 설치

```bash
python -m pip install --upgrade pip
python -m pip install PySide6
```

현재 저장소의 `requirements.txt`에 패키지가 등록되어 있지 않으므로, 실제 의존성을 확인한 후 해당 파일을 정리하는 것이 좋습니다.

의존성 파일을 정리한 뒤에는 다음 명령어로 설치할 수 있습니다.

```bash
python -m pip install -r requirements.txt
```

### 6.4. 프로그램 실행

```bash
python main.py
```

GUI가 실행되면 파일 선택 버튼을 눌러 분석할 `.ts` 파일을 선택합니다.

※ GUI 실행을 위해서는 현재 운영체제에서 Qt 창을 표시할 수 있는 환경이 필요합니다. WSL을 사용하는 경우에는 GUI 표시 환경도 확인해야 합니다.

## 7. 테스트 및 확인 사항

프로젝트를 검증할 때는 다음 항목을 확인할 수 있습니다.

| 테스트 항목 | 확인 내용 |
|---|---|
| 정상 TS 파일 | 패킷 수와 PID 통계가 정상적으로 계산되는지 확인 |
| Sync Byte 이상 데이터 | Sync Loss가 감지되고 재동기화가 시도되는지 확인 |
| CC 값이 비정상적인 데이터 | Continuity Counter 오류가 집계되는지 확인 |
| PAT/PMT가 포함된 파일 | 프로그램 번호, PMT PID 및 미디어 스트림 정보가 추출되는지 확인 |
| PMT에 정의되지 않은 PID | Unknown PID가 집계되는지 확인 |
| 불완전한 마지막 패킷 | 파일 끝의 불완전한 패킷이 감지되는지 확인 |
| 잘못된 파일 경로 | 파일 접근 오류가 적절하게 처리되는지 확인 |

테스트 결과를 문서화할 때는 실제 실행 결과와 사용한 테스트 파일을 함께 기록하는 것을 권장합니다.
